Expecta Write-back

Support.

Expecta Write-back lets your users edit and add rows in a Power BI report and save them to your data warehouse, as themselves and within their row-level security.

Contact us: waddah.alhajar@expecta.io
Support hours: 9:30–18:30, Rome time. When something fails, the visual shows a reference code: include it, so we can find the request.

Set up (administrators, once)

  1. Approve the application: a Microsoft Entra administrator consents to "Expecta Write-back" for your organisation. We send you the consent link.
  2. Power BI tenant setting: Admin portal → Tenant settings → Power BI visuals → AppSource Custom Visuals SSO → Enabled (for everyone, or for the groups that will edit).
  3. Add the visual from AppSource to your organizational visuals, so your report authors find it and you control updates.
  4. Licences: assign Expecta Write-back licences to the editing users in the Microsoft 365 admin center.
  5. Database: your database administrator gives the Expecta Write-back service access to the tables you want to edit (we provide the script), and we enable those tables on our side.
  6. Users who edit need Build permission on the report's semantic model.

Use (report authors)

  1. Add the visual. Row key: the column(s) that identify a row in the database table. Values: the columns to show; plain columns can be edited.
  2. Format pane → Connection: service URL, the semantic model's ID, the database table (schema.table) and the access columns (the columns your row-level security filters on; needed to add rows).
  3. Users edit cells or add rows, then Save. Only changed cells are sent.

Common messages

The visual saysWhat to do
"Power BI sign-in for visuals is turned off by your admin"Enable AppSource Custom Visuals SSO (step 2 above). A tenant setting can take a while to apply; then reload the report.
"Power BI didn't let us check your access…"The application isn't approved for your organisation yet (step 1), or the user lacks Build permission (step 6).
"You can't edit some of these rows" / "You can't add rows for these … values"Your row-level security doesn't include those rows. Nothing was saved.
"… is not enabled for write-back"Ask us to enable that table (step 5).
"Showing the first 1,000 rows"Use slicers or filters to reach the other rows.
"The write-back service hit an error, nothing was saved … reference …"Try again; if it repeats, send us the reference.

Limits

  • Rows can be edited and added, not deleted.
  • Up to 1,000 rows per visual, 200 changed cells and 50 new rows per save.
  • Editing needs a signed-in Power BI user, so it doesn't work in Publish to web. Embedded reports and Power BI Report Server are not tested yet.
